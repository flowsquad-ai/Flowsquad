Complete reference for Product Admins and team members -- product configuration, the Analyze tab in depth, and all ten SDLC workflow tabs.

1. Overview & Enterprise vs Evaluation

FlowSquad Enterprise is an AI-powered SDLC intelligence platform that transforms the way engineering teams produce and maintain software development artifacts. By connecting your codebase, documentation, and project tools into a single workspace, FlowSquad enables you to generate requirements, epics, user stories, tasks, solution designs, and test cases -- all grounded in your actual product knowledge.

FlowSquad ships with ten fully operational workflow tabs: Analyze, Refine, Epic, Story, Task, Design, Test Cases, Quality Score, Security Scan, and AskProduct. Every tab is production-ready and designed to support real engineering teams working at scale.

3. Part B — The Analyze Tab (In Depth)

⚠️
Product Admin action required before Regular Users can generate
The Analyze tab must be set up by a Product Admin or Global Admin first. Until at least one codebase has been loaded and analyzed, all downstream tabs (Refine, Epic, Story, Task, Design, Test Cases, Quality Score, Security Scan, AskProduct) display a “Please analyze the product first” warning and generation is blocked. Once analysis is complete the knowledge base is persistent — Regular Users can generate freely without re-analyzing.

The Analyze tab is divided into four sections: Product Codebases, Test Case Management, QA Automation Frameworks, and Product Documents.

Section 1 — Product Codebases

A product can have multiple codebases (backend API, React frontend, mobile app, microservices, etc.). Click ＋ Add Codebase to open the codebase dialog.

Codebase Input Methods

Two source types are available. Select the radio button that matches your setup:

MethodWhen to UseExample
📁 Local Path The codebase directory is accessible on the same host as FlowSquad. Use the full absolute path on disk. Windows installer: C:\Projects\MyApp\backend
Docker: copy code in first — docker cp /local/path flowsquad-app:/data/my-codebase — then use path /data/my-codebase
🔗 Clone from Git Clone directly from any Git server: GitHub, GitLab, Bitbucket, Azure DevOps, Gitea, self-hosted, etc. FlowSquad clones the repository on first Analyze and stores only the analysis index — the original Git URL is preserved permanently. Git URL + username + password or Personal Access Token. Source control credentials from Setup Wizard Step 5 are pre-filled if configured.
💡
Git credentials are session-only
Git credentials are never written to the database. They are stored in your browser session and are required on first Analyze and again after session expiry. On Refresh, FlowSquad prompts for credentials if they are no longer in session.

Analysis Configuration — Budget

Expand ⚙️ Analysis Configuration in the codebase dialog to set the LLM spend cap. The default of $3.00 covers most small-to-medium codebases. Raise it for large monorepos or lower it to limit cost during trial. Range: $0.50–$50.

Before every LLM call, FlowSquad checks the accumulated cost. If it has reached the budget, the remaining files are skipped and the analysis completes with the files already processed. Increasing budget after a partial analysis and clicking Re-analyze will resume from scratch with the higher cap.

Analysis Configuration — Exclude File Types

Four pre-built exclusion rules are provided as checkboxes, all enabled by default. Unchecking a rule includes those files back into analysis.

CheckboxFiles SkippedRecommended
Test Filestest/, *_test.*, *Test.*, *Spec.*✓ Leave on — focuses analysis on production code

Analysis Configuration — Custom Exclude Folders

Enter a comma-separated list of folder names to skip entirely. FlowSquad matches against the folder name anywhere in the path — you do not need to specify a full path.

Examples:

  • docs, Installers, License-tools — skip documentation and packaging folders
  • .venv, tests, fixtures — skip a virtual environment and test data
  • legacy, deprecated, archive — skip old code that is no longer active

Folder names are matched case-sensitively on Linux/Docker and case-insensitively on Windows. Use the exact folder name as it appears on disk.

Analysis Configuration — Custom Exclude File Types

Enter a comma-separated list of file suffixes or exact filenames to skip. Both glob-style suffixes and exact filenames are supported.

Examples:

  • *.md — skip all Markdown files
  • __init__.py — skip Python package init files (usually empty)
  • *.min.js, *.bundle.js — skip minified/bundled JavaScript
  • *.pb.go, *_generated.py — skip protobuf-generated files

Analysis Configuration — System Directory Exclusions

FlowSquad automatically skips a curated set of well-known system and tooling directories that never contain meaningful business logic. These are displayed as checkboxes in the 📁 System Directory Exclusions section, all pre-checked. You can uncheck any entry to include it in analysis if your project genuinely stores source code there.

Analysis Configuration — Analyse All Files

The 📋 Analyse all files checkbox bypasses the priority scoring algorithm. When checked:

  • All files that survive the exclusion filters are sent to the LLM in filesystem discovery order, not ranked order.
  • The LLM budget cap still applies — analysis stops when the budget is reached, regardless of how many files remain.
  • The Priority Weights section is greyed out (not used).

Use this mode when you want to guarantee that every file is considered (e.g. a small codebase where all files matter, or when priority ranking produces unexpected results). For large codebases, leaving this off and using priority weights is more cost-effective.

Analysis Configuration — Priority Weights

When Analyse all files is off, FlowSquad scores every file before selecting which ones to send to the LLM. Each file accumulates points based on its characteristics:

CharacteristicConditionDefault PointsWhat it means
🎯 Entry Point File is detected as a main program, command handler, app entrypoint, or route registration file 100 These files define what the application does at a high level — highest priority
📄 High LOC File has more lines of code than the Min LOC Threshold 50 Larger files tend to contain more logic worth understanding semantically
🔗 High Dependencies File is imported by many other files (a hub module) 30 Hub modules affect many parts of the system — understanding them has high leverage
🧰 High Complexity File has many decision points (cyclomatic complexity) 40 Complex files are more likely to contain nuanced business logic
📏 Min LOC Threshold Lines of code threshold for “High LOC” classification 500 Files below this line count do not qualify for the High LOC bonus

Scoring example: A file that is both an entry point (100) and exceeds the LOC threshold (50) and is imported by 20 other files (30) scores 180 points and is ranked near the top of the LLM selection list.

You can raise or lower individual weights to tune the selection for your codebase. For example, if your project has many thin entry points but business logic lives in service files, reducing the Entry Point weight and raising High Complexity will shift focus to the right files.

Click 🔄 Reset All to Defaults to restore factory values.

Managing Existing Codebases

  • Edit — click the pencil icon on a codebase card to update name, path, Git credentials, or any analysis configuration. Editing metadata alone does not trigger re-analysis.
  • Analyze — runs the full analysis pipeline. Shows the Pre-Analysis Preview before committing to LLM cost.
  • Refresh (↻) — incremental update. For Git codebases, FlowSquad fetches the latest commits first, then runs analysis only on files that changed since the last analysis. For local codebases, it compares file checksums directly. Much faster and cheaper than a full re-analysis.
  • Re-analyze — full fresh analysis from scratch. Use this after major structural refactors or after changing the LLM model in product settings. Deletes the previous index and rebuilds it entirely.
  • Delete (Product Admin only) — permanently removes the codebase index from the vector database. The source code itself is never stored by FlowSquad — only the analysis index is deleted.

How Analysis Works

FlowSquad performs five passes over the codebase. All exclusion rules are applied in Pass 1, so excluded files never consume any compute or LLM budget:

  1. Discovery & Exclusion — walks the directory tree, applies system dir exclusions, rule-based exclusions (test/config/build/migration), custom folder exclusions, and custom filetype exclusions. Only the surviving files proceed.
  2. Structural parse (tree-sitter) — extracts function signatures, class definitions, imports, and module boundaries from all surviving files. Language-agnostic and very fast. Produces complexity scores, dependency counts, and layer classifications (UI / API / Service / Data / Utility).
  3. Priority scoring & file selection — scores each file using the configured priority weights (or skips scoring if “Analyse all files” is on) and selects the highest-value files within the LLM budget estimate.
  4. Semantic analysis (LLM) — reads the selected files to understand intent, business logic, data flows, and API contracts. This is where LLM cost is incurred, capped by your budget. Each file is checked against the budget before the call is made.
  5. Vector indexing (ChromaDB) — embeds all extracted knowledge as vectors in the product knowledge base. All downstream tabs query this index at generation time.

The resulting knowledge is persistent — it survives page reloads and restarts. You only need to Refresh or Re-analyze when the codebase changes.

The Refine tab transforms raw, unstructured requirements into clean, structured, AI-refined requirement statements. This is typically the first generation step after loading your codebase in the Analyze tab.

⚠️
Requires analyzed product
If the Analyze tab has not been set up by a Product Admin, this tab displays a “Please analyze the product first” warning and generation is disabled.

Providing Input

Use the Smart Import panel to select one or more input sources (Manual Text, Upload Document, Jira, Confluence). All selected sources are combined and sent to the AI together. Click Generate once your sources are selected.

Generating Refined Requirements

FlowSquad's AI analyzes the input in the context of your loaded codebase and documents, removes ambiguity, resolves conflicts, and produces structured requirement statements with clarification questions. Answer all questions, then click Generate Refined Requirement.

Saving Requirements

ActionEffect
Save to Session Makes the refined requirements available to all other tabs in the current session (Epic, Story, Task, Design, Test Cases). Requirements are held in memory and do not persist after logout.

7. The Epic Tab

The Epic tab generates high-level work packages (epics) from your refined requirements. Epics represent major areas of functionality that will be broken down into stories in the next tab.

Generating Epics

Ensure refined requirements are loaded in the session (use Save to Session in the Refine tab first). Click Generate Epics. FlowSquad produces a set of epics grounded in your requirements and codebase context.

IT vs Non-IT Card View

Generated epics are displayed as cards in two tabs: IT (technical epics related to software development, infrastructure, or integrations) and Non-IT (business process, compliance, or documentation epics). Use the tab switcher to navigate between views.

Per-Card Actions

Each epic card provides the following actions:

  • View -- Open the full epic detail in a modal.
  • Edit -- Edit the epic title, description, and acceptance criteria inline.
  • Delete -- Remove the epic from the current view.
  • Push to Jira -- Create a Jira epic directly from this card using your configured Jira integration.
  • Download -- Download this epic as a Word document.
  • Save to Session -- Add this epic to the current session so it is available for story generation.
  • Save to DB -- Persist this epic to the database permanently.
  • Distribute -- Split this epic into multiple smaller epics.
  • Merge -- Combine this epic with one or more other epics into a single epic.

Bulk Actions

The bulk action bar appears when you select one or more cards using the checkbox in the top-left corner of each card. Bulk actions available: Select All, Bulk Save to Session, Bulk Save to DB, and Bulk Export (downloads all selected epics as a single Excel file).

View All Panels

At the bottom of the tab, two buttons provide access to persisted epics:

  • View All Epics in Session -- Displays all epics currently held in the session.
  • View All Epics in Database -- Displays all epics saved to the database for this product. From here you can load epics back into the session or delete them (Product Admins only).

10. The Design Tab

The Design tab generates a comprehensive Solution Design Document from your refined requirements and codebase context. The design document describes the proposed architecture, component interactions, data flows, and technical decisions in a format suitable for technical review and stakeholder sign-off.

Generating a Design -- Two-Step Flow

Design generation uses a two-step process to produce more accurate and contextually grounded documents:

  1. Step 1 -- Technical Questions: Click Generate Technical Questions. FlowSquad queries your analyzed codebase and asks the LLM to produce 5-8 architect-level clarification questions about the requirement. Review these questions -- they highlight ambiguous or under-specified areas that would affect the design.
  2. Step 2 -- Design Document: Answer the technical questions (or skip them) and click Generate Design. FlowSquad uses both the requirement and your question answers to produce a structured design document grounded in your codebase architecture.

You can skip Step 1 and click Generate Design directly from a requirement -- the technical questions step is optional but produces better results when requirements are complex or loosely defined.

Design Actions

  • Save to DB -- Persist the design document to the database. Future sessions can retrieve it from View All Designs in Database.
  • Push to Jira -- Create a Jira ticket containing the design document. The ticket is linked to your configured Jira project.
  • Push to Confluence -- Publish the design document as a Confluence page in your configured space. The page is created with proper headings and formatted for readability.
  • Download as Word -- Export the design document as a Word-compatible .doc file for distribution or offline editing.
💡
Design feeds Test Cases After saving a design to the session or database, the Test Cases tab can use it as a source for generating test cases. A design-driven approach typically produces more comprehensive test coverage than requirements-only generation.

12. The Quality Score Tab

The Quality Score tab provides an objective, multi-dimensional measurement of your product's test quality. It combines structural analysis of your codebase with semantic analysis of your test cases to produce an actionable score.

⚠️
Prerequisites Before running a quality scan, ensure that: (1) a codebase is loaded in the Analyze tab, and (2) test cases have been imported or generated and saved to the session or database.

Scoring Model

The Quality Score is calculated across three layers, with a maximum total of 100 points:

LayerMax PointsWhat It Measures
Layer 1 -- Test Density / Semantic Coverage 60 pts How thoroughly your test cases cover the codebase. Two scan modes available.
Layer 2 -- Automation Coverage 30 pts The ratio of automated test scripts to total test cases.
Layer 3 -- Bonus 10 pts Awarded when both Layer 1 and Layer 2 scores exceed 80%.

Layer 1 Scan Modes

  • Quick Scan -- Calculates test density using the ratio of test cases to code modules. Fast (typically seconds) and suitable for a high-level coverage baseline. Does not verify that individual functions are tested.
  • Deep Scan -- Uses AI to verify per-function test coverage. Reads each function in the codebase and determines whether a corresponding test case exists. Slower (minutes for large codebases) but produces a precise semantic coverage percentage.

Layer 2 -- Automation Coverage

FlowSquad counts the automated test scripts identified in your codebase (using the QA framework specified in the Analyze tab) and divides by the total number of test cases imported or generated. This ratio is scaled to the 30-point maximum.

Score Bands

Score RangeBandRecommended Action
90 – 100✓ ExcellentMaintain current coverage discipline.
80 – 89✓ GoodMinor gaps remain; target specific low-coverage modules.
70 – 79⚠ FairCoverage is acceptable but improvement is recommended before release.
60 – 69● PoorSignificant untested areas; prioritize test case authoring for high-risk modules.
< 60✗ CriticalCoverage is insufficient. Do not ship until coverage is improved.
💡
Use Deep Scan for release gates For release readiness decisions, always run a Deep Scan. The Quick Scan is useful during development sprints for a fast feedback loop, but only Deep Scan confirms that individual functions are actually covered by test cases.

13. The Security Scan Tab

The Security Scan tab performs an automated vulnerability analysis of your loaded codebase against the OWASP Top 10 -- the industry-standard list of the most critical web application security risks. No additional configuration is required beyond having a codebase loaded in the Analyze tab.

How It Works

FlowSquad's AI security scanner reads your codebase and identifies patterns associated with common vulnerability categories. The scan checks for:

  • SQL injection and NoSQL injection vulnerabilities
  • Cross-site scripting (XSS) risks
  • Authentication and session management flaws
  • Insecure direct object references
  • Security misconfiguration patterns
  • Sensitive data exposure (e.g., hardcoded credentials, unencrypted secrets)
  • XML External Entity (XXE) processing risks
  • Broken access control patterns
  • Use of components with known vulnerabilities
  • Insufficient logging and monitoring indicators

Running a Scan

Ensure a codebase is loaded in the Analyze tab. Navigate to the Security Scan tab and click Run Security Scan. The scan typically completes in 1-5 minutes depending on codebase size. Results are displayed as a vulnerability report with findings grouped by OWASP category, severity level, and affected file.

Viewing and Exporting Results

Each finding includes: the vulnerability category, affected file and line number (where applicable), a description of the risk, and a recommended remediation. Click Export Report to download the full vulnerability report as an Excel file suitable for security review meetings or compliance documentation.

⚠️
AI-assisted analysis The Security Scan provides AI-assisted pattern analysis. It is a development-time aid to highlight areas for review -- it does not replace a formal security audit or penetration test. Always validate findings with your security team before making remediation decisions.

14. The AskProduct Tab

The AskProduct tab is a conversational AI interface that lets you ask free-text questions about your product. FlowSquad searches across your entire loaded knowledge base -- codebase, uploaded documents, and generated artifacts -- and provides a precise answer with source references.

Asking Questions

Type a question in natural language into the chat input and press Enter or click Send. FlowSquad uses retrieval-augmented generation (RAG) to find the most relevant sections of your knowledge base and constructs an answer grounded in that content.

Example questions you can ask:

  • "What authentication methods does this product support?"
  • "Which modules handle payment processing?"
  • "What are the main API endpoints for user management?"
  • "Does this product currently implement rate limiting?"
  • "What does the requirements document say about offline mode?"

Chat History

Conversation history is maintained for the duration of your session, allowing follow-up questions and multi-turn conversations. The AI has context from previous turns in the same conversation. Chat history is cleared when you log out or start a new session.

  • Automation -- Test scripts and automation framework analysis from your QA codebase.

15. Session & Database Workflow

Understanding how FlowSquad manages data across sessions is essential for effective use of the platform. FlowSquad uses a two-tier data model: Session (temporary, in-memory) and Database (permanent, persisted).

How Artifacts Flow Through the Workflow

  1. Analyze tab loads data -- Codebase, documents, and test cases are indexed and become available as context for all generation steps.
  2. Generate artifacts -- In each tab (Refine, Epic, Story, Task, Design, Test Cases), click Generate to produce artifacts. Generated artifacts exist in the current view but are not yet persisted.
  3. Save to Session -- Click Save to Session on individual artifacts or use bulk save. Artifacts saved to the session are available across all tabs in the current session. The session persists until you log out.
  4. Save to DB -- Click Save to DB to permanently persist artifacts to the database. These artifacts will be available in all future sessions for this product.

Loading from Database into a New Session

When you start a new session, previously generated artifacts are not automatically loaded. To resume work from a prior session:

  • In each tab, click View All [Artifacts] in Database
  • Select the artifacts you want to use in the current session
  • Click Load to Session -- the selected artifacts are added to your session context and become available for the next generation step

The Proceed Button Chain

The Proceed button at the bottom of each tab navigates to the next tab in the workflow sequence: Refine -> Epic -> Story -> Task -> Design -> Test Cases -> Quality Score. Clicking Proceed does not automatically save artifacts -- ensure you have saved to session or database before proceeding if you want to use the current artifacts in the next tab.

ℹ️
Session timeout Sessions expire after the inactivity timeout configured by your administrator (default: 8 hours). Unsaved session data is lost on timeout. Save important artifacts to the database during long working sessions to avoid data loss.

Troubleshooting: Tab & UI Issues

AI Generation Returns No Results or Empty Output

Common causes and fixes:

  • No codebase loaded: Return to the Analyze tab and load your codebase before using generation tabs.
  • Nothing saved to session: In each tab, generated artifacts must be explicitly saved to Session or DB. Check that the previous tab's artifacts were saved to session before generating the next level (e.g., requirements must be in session before generating epics).
  • LLM API key expired or rate-limited: Ask your Product Admin or Global Admin to check Admin Panel -> LLM Configuration -> Test Connection.

Jira Push Fails -- "401 Unauthorized"

The Jira API token has expired or is invalid.

  1. Go to id.atlassian.com -> API tokens
  2. Create a new token named "FlowSquad Production"
  3. Update it in Admin Panel -> Settings -> Jira -> API Token -> Test Connection -> Save

Also verify you are using your email address (not just username) and that the Jira type is set correctly (Cloud vs. Server).

GitHub "Repository Not Found" for Private Repo

  • Verify the PAT has the repo scope: github.com/settings/tokens -> edit token -> enable "repo"
  • If your organisation enforces SAML SSO: go to the token settings -> Configure SSO -> Authorize next to your organisation
  • Update the token in Admin Panel -> Settings -> Source Control -> Test Connection

Quality Score Tab -- "No test cases loaded"

Import or generate test cases in the Analyze tab or Test Cases tab and save them to the Session or Database before running the Quality Score scan.

AskProduct Returns "I don't have information about this"

  • The knowledge base may be incomplete. Return to the Analyze tab and verify a codebase and relevant documents are loaded.
  • Rephrase the question more specifically -- AskProduct performs best with targeted questions about specific features, APIs, or modules.
  • If documents were recently added, wait 30 seconds for indexing to complete before querying.

Session Data Lost After Page Refresh

Session data (artifacts not yet saved to DB) is held in memory. A full page refresh or session timeout clears it. Always click Save to DB for artifacts you want to keep. The default session timeout is 8 hours of inactivity (configurable by your admin).

Frequently Asked Questions

How do I get started with FlowSquad?

On first access after installation, FlowSquad automatically launches the 9-step Setup Wizard. This wizard walks you through configuring your application database (PostgreSQL or MySQL), vector database (ChromaDB), LLM provider (OpenAI, Anthropic Claude, GitHub Models, or Ollama), authentication method, source control, collaboration tools, admin account, license key, and optional database encryption. Once the wizard completes, you are taken to the main dashboard where you can create your first product.

How does the Analyze tab work?

The Analyze tab is the knowledge intake hub. You load your codebase (from a Git URL, ZIP file, or local path), upload documents (PDFs, Word files, text files), and optionally load from Confluence. FlowSquad analyzes the codebase using tree-sitter parsing for syntax structure, LLM semantic analysis for understanding intent, and heuristic weighting. The resulting knowledge base is stored in the vector database and used by all downstream tabs -- Refine, Epic, Story, Task, Design, Test Cases, Quality Score, Security Scan, and AskProduct.

What is AskProduct and how do I use it?

AskProduct is FlowSquad's natural language Q&A interface. It queries your product's knowledge base -- which includes the analyzed codebase, uploaded documents, saved test cases, and automation artifacts -- and returns answers grounded in your actual product. To use it: load a codebase and documents in the Analyze tab first, then go to the AskProduct tab and type your question. Answers cite the source knowledge they drew from.

What is the difference between Quick Scan and Deep Scan in the Quality Score tab?
