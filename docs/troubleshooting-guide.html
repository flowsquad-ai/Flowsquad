Troubleshooting Guide

Cross-guide index of all known issues -- each entry links directly to the embedded resolution in the relevant guide. Includes a Diagnostic Quick Reference at the bottom.

How to Use This Page

Each issue below is documented in full inside the guide where it is most contextually relevant. Click the -> Go to resolution link to jump to the step-by-step fix. The Diagnostic Quick Reference at the bottom of this page is useful for initial triage when you don't yet know which category an error falls into.

ℹ️
Can't find your issue?
Enable Debug Mode (Admin Panel -> top nav bar -> Debug toggle) for verbose logs, then email support@flowsquad.ai with your FlowSquad version, the exact error message, and the last 50 lines of your log file.

Authentication Failures

SymptomLikely CauseResolution
LDAP: correct password still returns "Invalid credentials" Wrong Bind DN format, expired service account password, or LDAPS cert not trusted -> Setup Guide -- LDAP Troubleshooting
SAML / OAuth2: clicking “Login with SAML” or “Login with Keycloak” gives a 404 on the IdP URL The reverse proxy (nginx or IIS ARR) is rewriting the Location header of FlowSquad’s 302 redirect, replacing the IdP hostname with the FlowSquad hostname. The browser follows the rewritten redirect back to FlowSquad, which has no /realms/... route. nginx: add proxy_redirect off; inside the location / block — see Reference Guide — nginx.
IIS ARR: (1) in IIS Manager → server node → Application Request Routing Cache → Server Proxy Settings → uncheck “Reverse rewrite host in response headers” → Apply; (2) add the FlowSquad-PreserveIdPLocation outbound rule to web.config — see Reference Guide — IIS.
SAML: "Invalid SAML response" or "Signature validation failed" SP Entity ID mismatch, SP certificate not imported in IdP, or wrong attribute mapping -> Setup Guide — SAML Troubleshooting • Reference Guide — Keycloak SAML
SAML: [Errno 2] No such file or directory: …onelogin\saml2\schemas\saml-schema-protocol-2.0.xsd Running a build older than v1.1 where the onelogin package XML schema files were not bundled into the installer. The frozen executable cannot find the schema files it needs to validate the SAML response. Upgrade to the latest FlowSquad build. The fix is in all three installer specs (collect_all('onelogin')) and the custom_base_path passed to OneLogin_Saml2_Auth.
OAuth2: SSLError: certificate verify failed: self-signed certificate The Identity Provider (Keycloak, Okta, etc.) is using a self-signed TLS certificate. FlowSquad verifies SSL by default when calling the token and userinfo endpoints. In Setup Wizard → Step 4 → OAuth2, uncheck “Verify SSL certificate when connecting to Identity Provider” and save. Only do this in non-production environments; the correct long-term fix is to install a CA-signed certificate on the IdP.
OAuth2: "Invalid client ID" or "Unauthorized client" Wrong Client ID/Secret, redirect URI mismatch, or Azure admin consent not granted -> Setup Guide -- OAuth2 Troubleshooting
SAML: Keycloak redirect loop SP Entity ID / ACS URL port mismatch between Keycloak and FlowSquad -> Reference Guide — Keycloak SAML Troubleshooting

Enabling Debug Mode

Global Admins see a Debug toggle in the top navigation bar. Click it to enable verbose logging -- the indicator turns green when active. Debug logs include detailed API call timing, LLM request/response summaries, and database query information.

⚠️
Production Warning -- Debug mode exposes sensitive request details in logs. Enable only during active troubleshooting and disable immediately afterwards.

Contacting Support

Email support@flowsquad.ai and include:

  1. FlowSquad version (Admin Panel -> License Management)
  2. Exact error message text (copy from the UI or log)
  3. Log file excerpt -- last 50 lines from the log file location above
  4. Deployment type: Windows / Linux / Docker / Kubernetes
  5. Steps to reproduce the issue

Response times: 24 hours (Enterprise), 7 days (Evaluation).
