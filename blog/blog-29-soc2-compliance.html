From Zero to SOC 2 Compliant: How FlowSquad's Audit Trail, RBAC, and Encryption Support the Certification

Audit log every action, encrypt every API key, enforce MFA, control access with roles — FlowSquad ships with the controls SOC 2 auditors look for out of the box.
TL;DR
  • FlowSquad's built-in security controls address 9 of the 17 Common Criteria (CC) categories in SOC 2 Type II directly, with out-of-box evidence generation for each.
  • Field-level encryption (Fernet/AES-128) protects all LLM API keys and credentials at rest; key rotation takes under 4 minutes without downtime.
  • Audit logs capture 100% of user actions with immutable timestamps — a 90-day retention window satisfies the most common SOC 2 CC6 evidence request from auditors.

What SOC 2 Trust Service Criteria Does FlowSquad Address?

SOC 2 is built on five Trust Service Criteria (TSC): Security, Availability, Processing Integrity, Confidentiality, and Privacy. The most commonly audited — and the most complex to evidence — is the Security category, specifically the CC6 (Logical and Physical Access) series. FlowSquad's security architecture was designed with these criteria in mind, because the platform itself handles sensitive artifacts: LLM API keys, codebase data, design documents, and user management.

How Does FlowSquad's Audit Log Support SOC 2 CC6?

The SOC 2 CC6 criteria require that you demonstrate who accessed what, when, and what they did. FlowSquad's audit logs capture every user action at the application layer with five mandatory fields: timestamp (UTC, millisecond precision), user ID, action type, resource affected, and IP address. Logs are written to an append-only table in PostgreSQL and cannot be modified by any user role — not even global admin.

The most commonly requested audit log export during a SOC 2 Type II audit covers a 90-day lookback window. FlowSquad's admin panel exports this as CSV or JSON with one click, filtering by user, action type, date range, or resource. The export is timestamped and cryptographically signed, giving auditors confidence the log has not been tampered with since export.

Auditor Evidence Request (typical): "Provide a complete list of all user access events to system X for the period January 1 – March 31, 2026, including the action taken, resource affected, timestamp, and originating IP."

FlowSquad Response: Admin panel → Audit Logs → Export → Date range: Jan 1–Mar 31 → Format: JSON. Time to produce: under 60 seconds.

How Does RBAC Enforce the Principle of Least Privilege?

SOC 2 CC6.3 requires that system access is granted based on job function and revoked promptly when no longer needed. FlowSquad's RBAC implements 5 role tiers that map cleanly to the job functions in an SDLC team, ensuring no user has more access than their role requires.

Role assignments are logged in the audit trail — every grant, revocation, and modification. Auditors typically ask for an "access matrix" showing which users have which roles on which systems. FlowSquad exports this directly from the admin panel as a CSV. For SOC 2 Type II, you will need to demonstrate that you performed a quarterly access review — FlowSquad's admin panel includes a one-click "Access Review Report" button specifically to support this control.

How Does Field-Level Encryption Satisfy CC6.1?

SOC 2 CC6.1 requires protection of logical access credentials, including encryption of stored credentials. FlowSquad applies field-level encryption using Fernet (AES-128-CBC with HMAC-SHA256) to every sensitive field stored in PostgreSQL: LLM provider API keys, database credentials, OAuth tokens for GitHub/Jira/Confluence integrations, and SAML private keys.

The encryption key is stored separately from the database — in a Kubernetes Secret or external secrets manager (Vault, AWS Secrets Manager, Azure Key Vault). This means a database dump alone is useless without the encryption key — a critical separation that SOC 2 auditors explicitly look for under CC6.1's "logical access security measures."

Evidence for CC6.1: The platform's architecture document (auto-generated by FlowSquad's HLD generation feature) includes a data classification section showing which fields are encrypted, the encryption algorithm, and the key management approach. This document satisfies the "description of security measures" evidence typically requested.

Quarterly key rotation is a SOC 2 operational best practice. FlowSquad's key rotation wizard re-encrypts all stored secrets with a new Fernet key without downtime, completing in under 4 minutes for a typical deployment with 50 stored credentials. The rotation event is recorded in the audit log with the timestamp and the admin user who initiated it.

How Does MFA Reduce Access Risk?

SOC 2 CC6.6 requires that system access is protected against unauthorized access, including multi-factor authentication for remote access. FlowSquad supports MFA (TOTP-based, compatible with Google Authenticator, Authy, and 1Password) enforced at the platform level. When auth.mfaRequired: true is set in the Helm values, users cannot log in without MFA — there is no opt-out at the user level.

Industry data shows that MFA blocks 99.9% of automated account takeover attacks (Microsoft Security, 2023). For SOC 2, the evidence requirement is an MFA enrollment report showing that 100% of users have MFA enabled. FlowSquad's admin panel exports this report in one click, showing each user's MFA status and enrollment date.

Frequently Asked Questions

Does FlowSquad provide a SOC 2 report of its own?

Yes. FlowSquad maintains a SOC 2 Type II report covering the Security Trust Service Criteria. The report is available under NDA to customers and prospects. The controls described in this post — audit logs, RBAC, MFA, field-level encryption — are all covered in FlowSquad's own SOC 2 report, meaning your organization inherits these controls as part of a vendor due diligence argument. Contact sales@flowsquad.ai to request the report.

How long are audit logs retained by default?

The default retention period is 90 days, which satisfies most SOC 2 Type II audit windows. Retention can be extended to 365 days or indefinitely in the admin panel under Settings → Audit Logs → Retention Policy. Log storage is compressed at approximately 1.2 KB per event; a team of 20 engineers generating 500 events/day requires ~11 MB/month of storage — negligible cost compared to the compliance value.

Can FlowSquad integrate with our existing SIEM (Splunk, Datadog)?

Yes. FlowSquad's audit log API streams events in JSON-LD format via a webhook endpoint. Configure the webhook URL to point at your Splunk HEC, Datadog Log Intake, or Elastic Logstash endpoint. The webhook fires within 500ms of each event. Alternatively, use the PostgreSQL audit log table directly with a Splunk DB Connect or Datadog PostgreSQL integration for bulk historical ingestion.

Does RBAC work with SAML 2.0 / SSO groups?

Yes. When SAML 2.0 with Keycloak is configured, FlowSquad maps Keycloak group membership to FlowSquad RBAC roles via a configurable attribute mapping in the SAML assertion. For example, the Keycloak group flowsquad-analysts maps to the analyst role automatically on first login. Role changes in Keycloak are reflected at the user's next login. This means your organization's Identity team controls access through existing IAM tooling rather than a separate FlowSquad admin panel.

What encryption does FlowSquad use for data in transit vs. data at rest?

Data in transit is protected by TLS 1.3 enforced on all HTTP endpoints (the Ingress rejects connections below TLS 1.2). Data at rest uses field-level Fernet encryption (AES-128-CBC + HMAC-SHA256) for sensitive fields in PostgreSQL, and relies on the cloud provider's disk encryption (e.g., AWS EBS encryption with KMS, or GCP Persistent Disk encryption) for the full volume. The combination satisfies CC6.1 requirements for both in-transit and at-rest protection as documented in FlowSquad's own SOC 2 report.
